# 反应堆

反应堆演示**状态敏感结构**与物品、流体、能量三类 IO。它还有一处值得注意的结构 / 配方不一致：第二条配方需要能量输入，而结构没有提供能量输入安装条件。

## 入口与类型签名

| 类型 / 方法 | 签名与用途 | API 参考 |
| --- | --- | --- |
| `Machines` / `MachineDraft` | `machine(Identifier)`；`build()` → `MachineSpec` | [参考](../API/JavaAPI#machinedraft) |
| `AppearanceOptions` | `appearance(Consumer<AppearanceOptions>)` | [参考](../API/JavaAPI#appearanceoptions) |
| `Structures` / `StructureDraft` | `stateSensitive()`；`fullStructure(Consumer<StructureStageDraft>)`；`build(Identifier)` → `StructureSpec` | [参考](../API/JavaAPI#structuredraft) |
| `PatternDraft` / `BlockConditions` | `where(char, BlockCondition)`；`state(String)` | [模式](../API/JavaAPI#patterndraft)、[条件](../API/JavaAPI#blockconditions) |
| `Recipes` / `RecipeDraft` | `inputFluid(Fluid, int)`、`outputFluid(Fluid, int)`、`inputEnergy(long)`、`outputEnergy(long)` | [参考](../API/JavaAPI#recipedraft) |
| `FluidRequirementSpec` / `EnergyRequirementSpec` | 输入、输出分别保存为要求条目，`build()` 生成 `RecipeSpec` | [流体](../API/JavaAPI#fluidrequirementspec)、[能量](../API/JavaAPI#energyrequirementspec) |

## 机器定义

```java
private static final Identifier REACTOR = id("reactor");

public static void registerDefinitions(RegisterMachineDefinitionsEvent event) {
    if (!event.definitions().containsKey(REACTOR)) {
        MachineSpec machine = Machines
                .machine(REACTOR)
                .recipePool(REACTOR)
                .displayNameKey("machine.mmcr.reactor")
                .appearance(a -> a.machineBasicBlock(Identifier.parse("minecraft:blue_ice")))
                .build();
        event.registerMachine(machine);
    }
}
```

蓝冰为未成型主题方块。`recipePool(REACTOR)` 显式声明配方池，机器定义没有额外启用并行、多线程或修饰符。

## 完整状态敏感结构

```java
@SubscribeEvent
public static void registerStructures(RegisterMachineStructuresEvent event) {
    if (!event.structures().containsKey(REACTOR)) {
        StructureSpec structure = Structures
                .structure()
                .stateSensitive()
                .fullStructure(s -> s
                        .pattern(p -> p
                                .layer()
                                // ...省略
                                .where()
                                // ...省略
                                .controller('C')
                        )
                )
                .build(REACTOR);
        event.registerStructure(structure);
    }
}
```

### 状态敏感不是所有字符都固定状态

模式有 9 个切片，每片 8 行 × 9 列；空格未绑定，忽略对应世界位置。

默认结构状态不敏感；本例在 `StructureDraft` 上调用 `stateSensitive()`，使 `state(...)` 声明的属性参与匹配。楼梯的 `facing`、`half`、`shape`、`waterlogged` 因此具有实际约束，不只是预览装饰。

源码有 19 个 `state(...)` 绑定；字符 `a` 则仍使用 `block(Blocks.POLISHED_DEEPSLATE_STAIRS)`，只约束方块类型。开启状态敏感不会自动把所有 `block(...)` 变为默认状态匹配。

与 [紫珀炉](紫珀炉) 对照：紫珀炉也写出楼梯状态，但没有调用 `stateSensitive()`，实际匹配不强制这些状态属性。

### 接口集合

`X` 的并集条件允许物品输入 / 输出、流体输入 / 输出、能量**输出**或蓝冰。对外调用为 `BlockConditions.itemInput()`、`itemOutput()`、`fluidInput()`、`fluidOutput()`、`energyOutput()`，无需使用内部接口条件别名。

`N` 为绿宝石块，`O` 为青金石块；其余非楼梯装饰包括磨制深板岩、黑色染色玻璃、深板岩砖台阶、深板岩瓦和避雷针。装饰条件与端口条件不会互相替代。

## 两条配方

```java
@SubscribeEvent
public static void register(RegisterMachineRecipesEvent event) {
    RecipeSpec recipe = Recipes
            .recipe(REACTOR.withSuffix("_recipe_1"))
            .recipePool(REACTOR)
            .inputItem(Items.APPLE, 3)
            .inputFluid(Fluids.WATER, 1)
            .outputItem(Items.DIAMOND, 10)
            .outputFluid(Fluids.LAVA, 250)
            .outputEnergy(200)
            .duration(300)
            .build();
    event.registerRecipe(recipe);

    recipe = Recipes
            .recipe(REACTOR.withSuffix("_recipe_2"))
            .recipePool(REACTOR)
            .inputItem(Items.GOLDEN_APPLE, 2)
            .inputFluid(Fluids.WATER, 800)
            .outputItem(Items.GOLD_INGOT, 2)
            .outputFluid(Fluids.LAVA, 450)
            .inputEnergy(10)
            .outputEnergy(200)
            .duration(200)
            .build();
    event.registerRecipe(recipe);
}
```

### 基础参数

| 项目 | 配方 1 | 配方 2 |
| --- | --- | --- |
| 物品输入 | 3 苹果 | 2 金苹果 |
| 流体输入 | 1 mB 水 | 800 mB 水 |
| 物品输出 | 10 钻石 | 2 金锭 |
| 流体输出 | **250 mB 熔岩** | **450 mB 熔岩** |
| 能量输入 | 无 | 10 FE/t |
| 能量输出 | 200 FE/t | 200 FE/t |
| 时间 | 300 tick（15 秒） | 200 tick（10 秒） |

流体输入和输出是不同条目，本例消耗水、输出熔岩，不是同一种流体进出。1 桶 = 1000 mB；能量声明按 tick 计，不是整条配方总量。

### 能量输入与输出并存

`inputEnergy(long)` 与 `outputEnergy(long)` 分别创建 `EnergyRequirementSpec`，合法地同时出现在一条配方中。第二条名义净产出为 190 FE/t，但输入、输出仍分别检查并执行，不能把两条声明简化成 `outputEnergy(190)`；净值不取消输入供应要求。

`RecipeDraft` 的参数虽然是 `long`，当前常规能量声明要求正值并限制在 `Integer.MAX_VALUE` 范围内；流体数量使用正整数 mB。`Recipes.recipe(...)` 的 `build()` 返回 `RecipeSpec`，事件可按不同配方 ID 注册多条规则。

## 源码中的运行限制

:::warning
第二条配方调用 `inputEnergy(10)`，但结构的 `X` 并集没有 `BlockConditions.energyInput()`。按这份内置结构声明，无法在有效接口位置安装能量输入端口，因此配方 2 缺少它要求的常规能量输入来源。

教程保留该源码事实；若复制为自己的可运行示例，应同步设计能量输入安装位。仅看“净发电 190 FE/t”不能忽略 10 FE/t 的输入条件。
:::
