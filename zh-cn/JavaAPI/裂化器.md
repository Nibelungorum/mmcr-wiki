# 裂化器

裂化器演示**自定义控制器选项**、四切片结构与**物品 / 流体混合输出**。

## 机器定义与控制器

```java
private static final Identifier CRACKER = id("cracker");

public static void registerDefinitions(RegisterMachineDefinitionsEvent event) {
    if (!event.definitions().containsKey(CRACKER)) {
        MachineSpec machine = Machines
                .machine(CRACKER)
                .recipePool(CRACKER)
                .displayNameKey("machine.mmcr.cracker")
                .controller(c -> c
                        .id(CRACKER.withSuffix("_controller"))
                        .allowVerticalFacing(true)
                        .fullyRotationallySymmetric(true)
                )
                .build();
        event.registerMachine(machine);
    }
}
```

- `id(...)` 将控制器方块 ID 明确设为 `mmcr:cracker_controller`，它与机器 ID `mmcr:cracker` 是两个标识符。
- `allowVerticalFacing(true)` 在默认水平朝向之外允许朝上 / 朝下；它不是强制竖直放置。
- `fullyRotationallySymmetric(true)` 声明完全旋转对称的控制器表现。不要用“同一贴图”推导结构可以绕过朝向匹配；结构坐标仍由放置朝向参与转换。
- `recipePool(CRACKER)` 把机器绑定到裂化器配方池。

`controller(...)` 接受 `Consumer<ControllerOptions>`，回调中配置库提供的对象，无需创建或回传构建器。机器 `build()` 返回 `MachineSpec`。强制竖直放置的对照见 [怪物农场](怪物农场)。

## 多方块结构

```java
@SubscribeEvent
public static void registerStructures(RegisterMachineStructuresEvent event) {
    if (!event.structures().containsKey(CRACKER)) {
        StructureSpec structure = Structures
                .structure()
                .fullStructure(s -> s
                        .pattern(p -> p
                                .layer("AAA", "AAA", "AAA")
                                .layer("XBX", "B B", "XBX")
                                .layer("XDX", "D D", "XDX")
                                .layer("XEX", "ECE", "XEX")
                                .where('X', block(Blocks.POLISHED_DIORITE))
                                .where('A', block(Blocks.POLISHED_ANDESITE))
                                .where('B', any(
                                        BlockConditions.itemInput(),
                                        BlockConditions.itemOutput(),
                                        BlockConditions.fluidOutput(),
                                        BlockConditions.energyInput(),
                                        block(Blocks.BONE_BLOCK)
                                ))
                                .where('D', block(Blocks.BLUE_ICE))
                                .where('E', block(Blocks.LAPIS_BLOCK))
                                .controller('C')
                        )
                        .portTiers(t -> t
                                .minEnergyInput(PortTierLimits.EnergyTier.NORMAL)
                                .minItemInput(PortTierLimits.ItemTier.NORMAL)
                                .anyItemOutput()
                        )
                )
                .build(CRACKER);
        event.registerStructure(structure);
    }
}
```

四个切片各为 3×3。`A` 是磨制安山岩，`X` 是磨制闪长岩，`D` 是蓝冰，`E` 是青金石块。第二个切片的 `B` 是骨块或接口安装位：可装物品输入、物品输出、流体输出与能量输入。`C` 绑定本机控制器，空格为忽略位置。

所有 `layer(...)` 的行数与行宽需要一致，不能通过多写一行直接让某个切片变高。更复杂的外观用统一尺寸的空白行补齐，参考 [紫珀炉](紫珀炉)。

### 端口等级与端口类型

`portTiers(...)` 声明能量输入与物品输入至少 `NORMAL`，物品输出不限等级。物品枚举为 `TINY → SMALL → NORMAL → REINFORCED → BIG → HUGE → LUDICROUS`；流体另有 `VACUUM`，能量另有 `ULTIMATE`。

等级要求不改变模式里的方块允许集合。放置低级接口即使能匹配对应位置，也不能据此认为满足机器运行要求。反过来，增加 `anyFluidInput()` 等等级声明不会凭空增加流体输入安装位。

本例允许流体**输出**，但未在 `B` 条件中允许流体**输入**。修改配方增加流体输入时，也要同步增加结构的 `BlockConditions.fluidInput()`，仅写配方方法不足以让这台结构接收水。

## 物品与流体混合输出

```java
@SubscribeEvent
public static void register(RegisterMachineRecipesEvent event) {
    RecipeSpec recipe = Recipes
            .recipe(CRACKER.withSuffix("_recipe_1"))
            .recipePool(CRACKER)
            .inputItem(Ingredient.of(Items.LAPIS_LAZULI), 8)
            .inputItem(Items.COAL, 1)
            .outputFluid(Fluids.WATER, 500)
            .outputItem(Items.DIAMOND, 2)
            .inputEnergy(20)
            .duration(240)
            .build();
    event.registerRecipe(recipe);
}
```

基础加工：8 青金石 + 1 煤炭 → 500 mB 水 + 2 钻石，20 FE/t、240 tick（12 秒）。

- `Ingredient.of(...)` 是原版物品条件，可以扩展为多种候选物品；简单输入也能用 `inputItem(Item, int)`。
- `outputFluid(Fluid, int)` 的数量单位是 mB，1 桶 = 1000 mB。
- 多次调用输入 / 输出方法会追加各自要求，不会把前一个输出覆盖掉。
- `inputFluid(Fluids.WATER, amount)` 可声明流体输入，需配套结构安装位与可用资源。
- `build()` 返回 `RecipeSpec`，在 `RegisterMachineRecipesEvent` 中提交。重复检查针对配方 ID，不针对机器 ID。

## 小结

裂化器把控制器选项、方块条件、等级要求和加工 IO 分开声明：控制器由 [ControllerOptions](../API/JavaAPI#controlleroptions) 配置；模式由 [PatternDraft](../API/JavaAPI#patterndraft) 配置；接口条件来自 [BlockConditions](../API/JavaAPI#blockconditions)；配方 IO 来自 [RecipeDraft](../API/JavaAPI#recipedraft)。扩展任意一侧时，都应核对另一侧是否真的提供对应端口。
