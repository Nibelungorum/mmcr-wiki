# 裂化器 - 控制器朝向与旋转对称

本文演示一台支持**竖直朝向**与**完全旋转对称**的裂化器。代码对应三个文件：

- `example/startup_scripts/A_Vertical_Machine.js`
- `example/server_scripts/structure/A_Vertical_Machine.js`
- `example/server_scripts/recipe/A_Vertical_Machine.js`

这是 KubeJS 示例里**第一次**出现 `allowVerticalFacing()` 与 `fullyRotationallySymmetric()`，也是第一次用 `portRequirements(...)` 与 `portTierRequirements(...)` 显式约束端口数量与等级。

## 概览

裂化器 与 [高炉](高炉) 的关键差异在于**机器的物理摆放**与**端口的数量/等级约束**：

- 高炉 的控制器只能水平朝向。
- 裂化器 通过 `.allowVerticalFacing()` + `.fullyRotationallySymmetric()` 让控制器可以竖直放置。

`portRequirements(...)` 与 `portTierRequirements(...)` 是新工具，用于**约束端口的数量和等级下限**。

## 机器定义

`startup_scripts/` 目录下的 [A_Vertical_Machine.js](https://github.com/Nibelungorum/ModularMachinery-Community-Refoxed/blob/f234477b/example/startup_scripts/A_Vertical_Machine.js)：

```js
// Configure machine facing and rotational symmetry.

MMCREvents.startup(event => {

    const builder = event
        .createMachine("mmcr_kubejs:kubejs_cracker") // Create the machine definition.
        .displayNameKey("machine.mmcr_kubejs.kubejs_cracker") // Translation key for the display name.
        .recipePool("mmcr_kubejs:kubejs_cracker") // Bind the recipe pool.
        .allowVerticalFacing() // Allow the controller to be placed vertically.
        .fullyRotationallySymmetric() // Allow full rotation when the structure is placed vertically.

    builder.register()

    // See server_scripts/structure/A_Vertical_Machine.js for the rotatable structure.
})
```

`event.createMachine(...)` 返回 [MachineBuilderJS](../API/KubeJS#machinebuilderjs)。链式调用：

- `.allowVerticalFacing()`：声明控制器**可以竖直放置**，即面朝上或面朝下。  
    详见 [MachineBuilderJS.allowVerticalFacing](../API/KubeJS#machinebuilderjs)。  
    默认 `false`，即只允许水平朝向。  
    开启后玩家右键放置时可以选朝上、朝下、朝南北东西六种朝向中的任意一种。  
- `.fullyRotationallySymmetric()`：声明竖直朝向下可尝试四种水平滚转方向的结构匹配。  
    详见 [MachineBuilderJS.fullyRotationallySymmetric](../API/KubeJS#machinebuilderjs)。  
    默认 `false`。  
    未启用时按控制器的 `ROLL_FACING` 匹配，启用后依次尝试四种候选滚转方向。这个开关不修改 front / side / top / bottom 的纹理 ID。  
- `.recipePool("mmcr_kubejs:kubejs_cracker")`：配方池 ID。

`builder.register()` 终结，把机器提交到启动期注册窗口。

:::info 备注
与 [蒸馏塔](蒸馏塔) 不同，这台机器**没有调用 `.expandableStructure(true)`**。裂化器只有一个固定形态，不需要分组，结构脚本用扁平式 API 即可。
:::

启动期窗口不可热加载，修改后必须重启游戏。

## 多方块结构

`server_scripts/structure/` 目录下的 [A_Vertical_Machine.js](https://github.com/Nibelungorum/ModularMachinery-Community-Refoxed/blob/f234477b/example/server_scripts/structure/A_Vertical_Machine.js)：

```js
MMCREvents.server(event => {
    const api = event.getAPI()
    const structure = event.createStructure("mmcr_kubejs:kubejs_cracker")

    structure
        .pattern(['AAA', 'AAA', 'AAA'])
        .pattern(['XBX', 'B B', 'XBX'])
        .pattern(['XDX', 'D D', 'XDX'])
        .pattern(['XEX', 'ECE', 'XEX'])
        .set('X', api.block('minecraft:polished_diorite'))
        .set('A', api.block('minecraft:polished_andesite'))
        .set('D', api.block('minecraft:blue_ice'))
        .set('E', api.block('minecraft:mossy_cobblestone'))
        // Previous examples used fixed ports. A const structure also provides convenient port predicates.
        .set('B', api.anyOf(
            api.anyOfItemInput(),
            api.anyOfItemOutput(),
            api.anyOfFluidOutput(),
            api.anyOfEnergyInput()
        ))
        .controller('C')
        // Set the required port counts. The structure will not form when these requirements are not met.
        // 单个数字为最小数量；二元数组为最小与最大数量。
        .portRequirements(api.portRequirements({
            item_input_bus: 1,
            item_output_bus: 1,
            fluid_output_hatch: 1,
            energy_input_hatch: [1,3] // Allow one to three energy input hatches.
        }))
        // Set port tier requirements using a readable string format.
        .portTierRequirements(api.portTierRequirements([
            'item_input_bus>=normal',
            'item_output_bus>=normal',
            'energy_input_hatch>=normal'
        ]))

        .build()
})
```

`MMCREvents.server(event => {...})` 回调里的 `event` 是 [MMCRServerEventJS](../API/KubeJS#mmcrservereventjs)。
`event.getAPI()` 返回 [KubeJSApi](../API/KubeJS#kubejsapi)。

与 [高炉](高炉) 相比，本机器的结构新增了两个工具：

1. **`.portRequirements(...)`**：端口数量需求。
    详见 [MachineStructureBuilderJS.portRequirements](../API/KubeJS#machinestructurebuilderjs) 与 [KubeJSApi.portRequirements](../API/KubeJS#port-requirements)。
2. **`.portTierRequirements(...)`**：端口等级下限。
    详见 [MachineStructureBuilderJS.portTierRequirements](../API/KubeJS#machinestructurebuilderjs) 与 [KubeJSApi.portTierRequirements](../API/KubeJS#port-requirements)。

**如果端口数量或等级不满足需求，结构直接判定为成型失败**。

### `portRequirements` 的写法

参见 [KubeJSApi.portRequirements](../API/KubeJS#port-requirements)：

```javascript
api.portRequirements({
    item_input_bus: 1,           // 至少 1 个物品输入总线
    item_output_bus: 1,          // 至少 1 个物品输出总线
    fluid_output_hatch: 1,       // 至少 1 个流体输出仓
    energy_input_hatch: [1,3]    // 至少 1、最多 3 个能量输入仓
})
```

- 单个数字 → 最小数量，内部调用 `PortRequirementSpec.Builder.min(...)`。
- 二元数组 `[min, max]` → 闭区间 `[min, max]`。

精确数量要写 `[n, n]`；数字 `0` 不限制数量，要禁止某类端口应写 `[0, 0]`。官方脚本注释说单个数字是 exact count，但与此提交的 `KubeJSApi.portRequirements` 实现不符。

映射键是**端口族统计别名或具体端口种类 ID**，与 `'B'` 字符无关。这里的 `item_input_bus` 统计全部等级的物品输入端口，也包括声明了物品输入族的复合、扩展与联动端口；`item_input_bus_tiny` 则只统计该型号。普通 `normal` 型号的 ID 与族别名重名，不能用 `item_input_bus` 单独计数 `normal` 型号。

玩家能在 `'B'` 位置放哪些方块由 `.set('B', ...)` 决定；本例允许物品输入、物品输出、流体输出与能量输入端口。数量需求只校验这些位置实际放置的端口，不会自动添加安装位。

### `portTierRequirements` 的写法

参见 [KubeJSApi.portTierRequirements](../API/KubeJS#port-requirements)：

```javascript
api.portTierRequirements([
    'item_input_bus>=normal',
    'item_output_bus>=normal',
    'energy_input_hatch>=normal'
])
```

有等级的端口族使用 `端口族>=等级`，例如 `item_input_bus>=normal`，运算符不是 `=>`。等级名称不区分大小写，但端口族必须按小写名称精确匹配，整项不能加入空格。各族可选等级为：

- 物品：`tiny`、`small`、`normal`、`reinforced`、`big`、`huge`、`ludicrous`。
- 流体：上述 + `vacuum`。
- 能量：上述 + `ultimate`。
- Mekanism 普通化学品：`basic`、`advanced`、`elite`、`ultimate`。

Mekanism 放射性化学品与热量端口没有等级参数，只写端口族，不追加 `>=any` 或其他等级。以下是额外的语法示例：

```javascript
api.portTierRequirements([
    'chemical_input_hatch>=advanced',
    'chemical_output_hatch>=ultimate',
    'radioactive_chemical_input_hatch',
    'radioactive_chemical_output_hatch',
    'heat_input_hatch',
    'heat_output_hatch'
])
```

这些需求也可通过 `chemicalInputTier(String)` / `chemicalOutputTier(String)`、`radioactiveChemicalInputTier()` / `radioactiveChemicalOutputTier()`、`heatInputTier()` / `heatOutputTier()` 创建；门面与三个构建器均提供这些快捷工厂。完整规则见 [API：端口等级与端口需求](../API/KubeJS#port-requirements)。应用到结构时，还需在模式中提供安装位并通过 `.set(...)` 允许相应端口；Mekanism 未加载时，没有对应端口能满足这些需求。

本例要求物品输入、物品输出、能量输入**各至少有一个端口达到 `normal`**，不要求所有同族端口都达标。只有 `tiny` 物品输入总线时无法成型；若结构有额外安装位，同时存在 `normal` 或更高等级的物品输入端口，低等级端口可以共存。每项等级需求都必须满足，但同一个端口可满足多项兼容需求；要限制数量仍需配合 `portRequirements(...)`。

## 配方

`server_scripts/recipe/` 目录下的 [A_Vertical_Machine.js](https://github.com/Nibelungorum/ModularMachinery-Community-Refoxed/blob/f234477b/example/server_scripts/recipe/A_Vertical_Machine.js)，下列保留完整输入输出：

```js
ServerEvents.recipes( event => {

    // This example focuses on fluid output rather than recipe complexity.
    event.custom({
        type: 'mmcr:machine_recipe',
        recipe_pool: 'mmcr_kubejs:kubejs_cracker',
        tick_time: 300,
        requirements: [
            { type: 'minecraft:item', io: 'input', item: 'minecraft:apple', count: 3 },
            { type: 'minecraft:item', io: 'output', stack: { id: 'minecraft:iron_ingot', count: 10 } },
            {
                type: 'minecraft:fluid', // Set the requirement type to fluid.
                io: 'output',
                stack: {
                    id: 'minecraft:water', // Fluid identifier.
                    amount: 1000 // Amount in mB.
                }
            },
            { type: 'minecraft:fluid', io: 'output', stack: { id: 'minecraft:lava', amount: 1000 } },
            { type: 'minecraft:item', io: 'output', stack: { id: 'minecraft:gold_ingot', count: 10 } },
            { type: 'minecraft:item', io: 'output', stack: { id: 'minecraft:diamond', count: 10 } },
            { type: 'minecraft:item', io: 'output', stack: { id: 'minecraft:coal', count: 10 } },
            { type: 'minecraft:item', io: 'output', stack: { id: 'minecraft:stick', count: 10 } },
            { type: 'minecraft:item', io: 'output', stack: { id: 'minecraft:water_bucket', count: 1 } },
            { type: 'neoforge:energy', io: 'input', fe_per_tick: 20 }
        ]
    })
    // Recipe IDs are optional in KubeJS.
})
```

值得注意的地方：

1. 流体输出使用 `type: 'minecraft:fluid'` + `stack: { id, amount }` 形式，amount 单位是 mB。
2. 能量输入 `fe_per_tick: 20` 需要实际的输入仓、供电与传输能力；数量与等级约束不是供电保证。
3. 没有调用 `.id(...)`：KubeJS 会自动生成 ID。

字段含义详见 [MachineRecipeSchema](../API/KubeJS#machinerecipeschema)。

数据驱动的配方支持热加载，修改后 `/reload` 即可。

:::warning 官方完整配方的端口容量
上述结构只有 4 个 `B` 位。满足物品输入、物品输出、流体输出、能量输入四种最低需求后，流体输出仅剩一个仓位；完整配方却同时输出水和岩浆，且没有开启 `allow_partial_outputs`。单流体输出仓不能同时接受两种流体，因此“结构成型”不保证该完整配方能执行。

要保留完整配方，应扩充结构的端口位并提供足够的独立流体输出容量；要保持原结构，也可删去一种流体输出。这是修改教程时应明确的设计选择，不能悄悄省略产物后声称原示例可运行。
:::

## 特殊机制：朝向 / 旋转 / 端口数量约束


### `allowVerticalFacing` / `fullyRotationallySymmetric` / `requireVerticalFacing`

三个方法都在 [MachineBuilderJS](../API/KubeJS#machinebuilderjs) 中：

| 方法 | 默认值 | 行为 |
| --- | --- | --- |
| [`allowVerticalFacing()`](../API/KubeJS#machinebuilderjs) | `false` | 允许控制器竖直朝向，即面朝上或面朝下。开启后玩家可以摆出"塔式"或"井式"形态。 |
| [`fullyRotationallySymmetric()`](../API/KubeJS#machinebuilderjs) | `false` | 竖直朝向下尝试四种水平滚转的结构匹配，不是统一纹理。 |
| [`requireVerticalFacing()`](../API/KubeJS#machinebuilderjs) | `false` | 强制竖直朝向，开启时自动启用 `allowVerticalFacing`。玩家无法放置水平朝向的控制器。 |

#### 差异

- **`allowVerticalFacing` 是放行开关**：开启后玩家既可以水平也可以竖直放置。
- **`requireVerticalFacing` 是强制开关**：开启后玩家**只能**竖直放置。它会自动启用 `allowVerticalFacing`，所以不需要两个都调。
- **`fullyRotationallySymmetric` 是结构匹配开关**：主要影响竖直朝向的候选滚转，外观仍由纹理配置决定。

#### 组合

裂化器 的组合是 `.allowVerticalFacing() + .fullyRotationallySymmetric()`：

- 玩家**可以**水平或竖直放置。
- 竖直放置时，MMCR 可尝试四种滚转方向匹配结构；不代表所有方块状态都能任意旋转。

如果你的机器**只能竖直放置**，例如重力驱动的离心机，改用 `.requireVerticalFacing()`，玩家无法放错方向。

如果需要固定竖直滚转方向，可以省略 `.fullyRotationallySymmetric()`。是否使用统一外观应另行配置控制器纹理，不应拿这个结构开关代替纹理设置。

### `portRequirements` 与 `portTierRequirements`


参见 [KubeJSApi.portRequirements](../API/KubeJS#port-requirements)：

```javascript
api.portRequirements({
    item_input_bus: 1,           // 最小数量
    item_output_bus: 1,
    fluid_output_hatch: 1,
    energy_input_hatch: [1,3]    // 区间 [min, max]
})
```

参见 [KubeJSApi.portTierRequirements](../API/KubeJS#port-requirements)：

```javascript
api.portTierRequirements([
    'item_input_bus>=normal',
    'item_output_bus>=normal',
    'energy_input_hatch>=normal'
])
```

数量需求统计匹配端口的总数；每项等级需求检查是否至少有一个同族、同方向的端口达到最低等级。两者独立校验。

#### 端口 ID 与字符的区别

`item_input_bus` 在这些需求中表示**物品输入端口族**，不是模式字符。`'B'` 绑定的方块谓词决定该位置允许哪些方块，端口数量与等级需求再校验实际放置的端口。

数量需求可使用族别名或具体型号 ID；等级列表只接受规定的端口族写法，不能把 `item_input_bus_tiny` 等具体型号 ID 放在 `>=` 左侧。

## 小结

1. **`allowVerticalFacing()` / `fullyRotationallySymmetric()` / `requireVerticalFacing()`**：允许竖直、尝试竖直滚转、强制竖直三个独立配置。都有无参启用与 `(boolean)` 重载，默认 false，`requireVerticalFacing(true)` 自动启用竖直放置。
2. **`portRequirements(...)` + `portTierRequirements(...)`**：结构对端口数量与最低等级的硬约束。
详见 [MachineStructureBuilderJS](../API/KubeJS#machinestructurebuilderjs) 与 [KubeJSApi](../API/KubeJS#kubejsapi)。
3. 配方可以同时输出物品与流体：`type: 'minecraft:fluid'` + `stack: { id, amount }`。
